## 1. 本轮结论

在已有六项只读研究工具之上，已补齐“预算预检 → 固定提案 → 人工批准 → 共享原任务队列 → 查询实际结果”的核心闭环。全仓 400 项测试通过；三股真实行情在三个独立进程中验证，重开后没有重复任务。

这不是完整聊天智能体交付：本轮没有连接任何聊天模型，没有调用外部模型 API，没有研究记忆、自动研究包或因子追踪调度。下一阶段保持 P1B，不跳过开发顺序。

P1A 仍保留明确边界：批准时没有冻结行情字节；没有新增严格 PIT 或官方历史规则认证；规模预算不是物理资源隔离。本轮结果不能替代全平台原生客户端逐项验收。

## 3. 数据与研究约束

预检不加载行情，只说明配置与估算规模通过；不说明资料完整、历史可知或存在 Alpha。数据在执行时仍由原研究引擎读取并保存快照，不能称为批准时的数据冻结。

原有 qfq 研究默认值、因子公式、费用和公司行动口径没有修改。历史资格算法仍使用原有资料；缺失时由原引擎报错，不由助手静默改成别的口径。

模型提案暂时拒绝 `universe.reference_manifest` 任意文件路径；用户仍可在原人工研究入口选择已有资料。JSON 大小限制为 64 KiB，重复字段、非有限常量、过深嵌套与过多元素会被拒绝。

这是 `ResearchBudget` 的宿主配置，不允许模型在工具参数中抬高预算；本轮没有制作预算设置表单。规模量是前置估算，不是内存、CPU、存储或精确耗时承诺。活动任务限制约束新提案的入队检查，不改变原人工研究任务的既有权限。

时限从实际执行开始计算，不包含排队时间；到达检查点才停止。正在运行的原生计算不能被这套机制强行抢占，不把它称作硬资源沙箱。恢复任务是显式操作，每次执行使用原批准预算。

## 5. 提案与批准状态

模型工具只能预检、保存和读取提案。待人工批准的提案超过 24 小时需要重新生成；配置、代码、依赖、预算或工作空间变化也不能静默沿用。完整校验值与用户当前核对的记录绑定。

批准先持久保存，再交给原队列；若队列接收后回执丢失，提案保留已批准状态，重试寻找原 UUID。已交付任务的日志丢失时，拒绝自动新建替代任务。已取消或中断任务仍在原任务页显式恢复，不通过重复批准偷偷重跑。

存储位置为所选研究产物目录下的 `_agent/proposals.sqlite3`，含提案与状态事件。使用参数化 SQLite 事务；每份提案有内容校验值，但不宣称它是对恶意本地文件修改者的密码学认证。

## 6. 使用入口

重新启动牛牛后：顶栏“AI 研究接口” → “研究提案与人工批准”。先用原业务表单填草稿，或粘贴实验配置；点击“仅预检配置与预算”，再保存待批准提案。

从列表选择已保存提案，在中文分层明细里核对原配置、解析结果、预算及限制。勾选确认后点击“批准选中提案并提交”。批准的是选中的固定记录，不是上方未保存草稿；预检草稿会清除原提案的批准选中状态。

任务交给原队列。可在此查询状态并打开实际结果，也可在原“运行任务”页取消/恢复。关闭提案窗口不另建任务、不自动取消已批准任务。

JSON CLI 保留原只读用法；显式传入数据工作空间后开放九项查询/提案工具：

```bash
cd /Volumes/Lexar/niuniu
.venv/bin/python -m quantlab.agent --output artifacts \
  --data-root /Volumes/Lexar/MQC-DATA --schemas
.venv/bin/python -m quantlab.agent --output artifacts \
  --data-root /Volumes/Lexar/MQC-DATA --call get_capabilities
```

`preview_experiment` 参数为 `spec_json`；`propose_experiment` 参数为规范 UUID `request_id` 和 `spec_json`；`get_proposal` 参数为 `proposal_id`。重复工具调用须复用原 request_id；换配置需要新编号。

CLI 不提供批准或研究提交动作，实际调用 `approve_and_submit` 返回 UNKNOWN_TOOL，退出码 2。批准入口只在宿主服务及人工桌面流程中使用。
