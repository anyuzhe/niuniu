## 1. 固定增量证据包

新增候选增量证据计划，执行前冻结：候选 run、1–5 个控制因子、训练截止、持有期、family alpha，以及可选的成本后候选/基准账户和评价起点。
残差增量直接复用现有训练期控制投影与样本外 residual IC；成本后增量直接复用现有兼容账户日收益比较。
一个包中的全部测试槽位一起进入 Holm FWER 校正。失败或不可检验槽位继续占计划名额，不因失败缩小检验族。
子研究使用确定性 run_id；重启时复用已完成子项，已明确失败并保存的槽位不会自动重试。
父增量证据包已接入冻结复算：可用子项重新复算，失败槽位保持未知，重新计算原完整族 Holm，并要求统计语义一致。

模型工具只有 `preview_incremental_evidence`、`propose_incremental_evidence`、`get_incremental_evidence`；没有批准或执行工具。
宿主“候选增量证据包”窗口必须人工勾选确认，选择提案本身不会启动研究。

## 2. 受限 DSL 候选

新增固定因子 `DSL.RESTRICTED@1.0.0`。表达式不是字符串代码，而是结构化 AST 参数。
第一版白名单包含基础价格/成交字段、常数、四则运算、过去滞后、差分/收益、单层滚动统计及同一时点截面排名；节点数、深度、窗口和滞后均有限制。
不支持负 shift、未来引用、任意函数名、任意文件/网络/Shell、动态 Python 或 `eval`；第一版也禁止滚动/滞后内部再嵌套时序操作，避免含糊窗口语义。

候选预览使用已有 replay 归档中的真实 `bars.parquet`，先验证 AST，再计算值，并在两个历史截点执行前缀不变性检查。
候选注册保存不可变 AST、来源 run 指纹、代码/环境指纹和验证摘要；注册不会创建研究任务，也不认证 Alpha。
模型可以 `preview_dsl_candidate`、`propose_dsl_candidate`、`list_dsl_candidates`、`get_dsl_candidate`，但没有注册工具。
宿主“受限 DSL 候选注册”窗口必须人工确认后才注册；注册后真正研究仍走原 `prepare → 提案/审批 → JobQueue → ExperimentRunner → 归档/复算`。

## 5. 当前边界

第 7 步的工程主体已经闭环，但这不代表系统可以自动发现稳定 Alpha。模型提出的 DSL 候选仍必须人工注册，研究计划仍必须按既有审批边界执行。
