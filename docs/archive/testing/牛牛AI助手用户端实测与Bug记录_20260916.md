## 3. Bug 修复记录

### BUG-01：Codex CLI 一发送就提示连接结束

- 现象：连接/发送时报 `Codex 连接已结束；请检查 CLI 登录与配置`。
- 根因：Codex CLI 0.132.0 会先解析全局 `~/.codex/config.toml`；其中旧 `[agents]` 字段和不兼容 MCP transport 会让 CLI 在应用覆盖参数生效前退出。
- 修复：子进程使用临时隔离的 `CODEX_HOME`，只复制现有 `auth.json`（权限 0600）以复用 ChatGPT 登录；不读取或修改全局配置，退出时清理临时目录。
- 相关文件：`src/quantlab/agent/codex_options.py`、`src/quantlab/agent/codex_transport.py`、`tests/test_codex_provider.py`。
- 验收：界面“测试连接／刷新模型”成功返回 5 个模型，两轮真实问答均完成；会话日志记录警告“仅本进程隔离 Codex 配置；未修改全局配置”。

### BUG-02：数据版 AI 助手覆盖了完整研究工具

- 现象：数据工作台把 `ChatRuntime.api` 整体替换成 `MarketDataResearchAPI`，导致 Research Skill、Playbook、Peer Review 和 Research Session Grant 工具消失；模型只能凭通用概念杜撰“郑希逻辑”。
- 根因：`DataResearchChatDialog` 不是在完整 API 上叠加行情工具，而是直接覆盖 API。
- 修复：新增合作式 `DataConnectedResearchAPI`，合并行情、完整研究、Peer Review、Research Skill 和 Session Grant 工具，并去重 schema。
- 相关文件：`src/quantlab/desktop/data_workbench.py`、`tests/test_baostock_desktop.py`。
- 验收：界面实际调用 `list_research_skills`、`get_research_skill`、`search_research_skill_items`，并返回郑希精确 package snapshot。

### BUG-03：Research Skill 检索耗尽工具预算，最终无答复

- 现象：首次实测先用空 `item_type` 调用失败；随后把多个关键词当成必须连续出现的整句，零命中后反复宽泛检索，最终报“已达到本轮工具调用预算”。
- 根因：`item_type` schema 没有枚举约束；多关键词 query 仅做整段子串匹配；系统提示未约束检索次数。
- 修复：
  - 为 `item_type` 增加 `CLAIM/HYPOTHESIS/ALIGNMENT/RESOURCE` 枚举并在宿主校验。
  - 空格、逗号、分号、斜杠分隔的多关键词改为“任一词命中”。
  - 系统提示要求一次合并关键词，方法全貌最多各查询一次 CLAIM 与 HYPOTHESIS。
- 相关文件：`src/quantlab/agent/research_skill_tools.py`、`src/quantlab/knowledge/research_skill_library.py`、`src/quantlab/agent/chat_runtime.py`、`tests/test_research_skill_library.py`。
- 验收：同样的宏景科技问题由失败的 12 次上限降为 9 次工具调用并正常生成完整答复。

### BUG-04：Research Skill 证据标签为空且无法核对

- 现象：证据区曾显示 `research_skill · `、`research_skill_item · `，点击“打开选中的真实引用”没有对应分支。新增独立技能库弹窗后，在 macOS 辅助功能自动化下还会触发 `libqcocoa` 的 `EXC_BAD_ACCESS`。
- 根因：证据标题没有识别 `skill_key/item_id/resource_id`；`ResearchChatDialog.open_reference` 没有 Research Skill 处理；另开动态表格窗口与 macOS 辅助功能读取存在不稳定交互。
- 修复：证据列表显示实际技能/条目/资源 ID；点击后异步读取精确 snapshot，并在当前助手窗口的“业务明细”区域展示只读引用，避免新开顶层窗口。
- 相关文件：`src/quantlab/desktop/research_chat.py`、`tests/test_research_chat_desktop.py`。
- 验收：用户端选择 `growth-style-quote` 后成功显示 `CLAIM`、snapshot、`total=1` 和解释边界，应用保持运行。

### BUG-05：全交易经验查询耗尽 12 次预算后整轮无回答

- 现象：补充实测会话 `d54fa304-cb8f-4c57-aaae-7e69d84f5dfe` 在约 30 秒内完成 12 次模型工具调用；模型尝试第 13 次调用时被硬终止，用户区只有“已达到本轮工具调用预算”，没有任何分析正文。
- 预算核对：当时实际配置为 `max_tool_calls=12`、`max_rounds=16`；宿主自动取得的宏景科技实时行情不计入这 12 次。
- 消耗明细：模型重复调用 `list_playbook_definitions` 3 次；另有一次 `search_factors` 因 `limit` 越界失败但仍占预算；其余预算用于 Research Skill、StrategySource、研究记忆、因子、MarketSnapshot 和 PlaybookCase。
- 根因：12 次适合单一问题，但不足以覆盖七类交易经验；更关键的是 Provider 在超过上限时直接抛错，没有把“停止查询并用已有证据收尾”返回给模型。
- 修复：
  - 当前项目配置从 12 调整为上限 24 次；仍保持有限预算，不允许无限调用。
  - 与 24 次工具预算配套，将当前项目上下文字符预算从 60000 调整为 120000，并为最终正文预留独立空间。
  - 系统指令要求合并检索条件、复用列表结果、避免无新证据的重复查询，并明确参数失败同样消耗预算。
  - Codex CLI 与 HTTP Provider 在预算耗尽时返回结构化 `TOOL_BUDGET_EXHAUSTED`，阻止继续查询并要求模型基于已有证据作答；HTTP 收尾请求不再暴露工具。
- 相关文件：`src/quantlab/agent/chat_runtime.py`、`src/quantlab/agent/provider_compat.py`、`src/quantlab/agent/codex_provider.py`、`src/quantlab/agent/http_provider.py`、`tests/test_codex_chat_protocol.py`、`tests/test_chat_http_provider.py`。
- 验收：最终相同问题使用 18 次模型工具调用完成回答，24 次上限留有余量。

### BUG-06：Playbook / StrategySource / Case 证据显示空白 ID

- 现象：全经验实测右侧证据列表出现 `playbook_definition · `、`strategy_source · `、`playbook_case · `，用户无法分辨或核对具体引用。
- 根因：桌面引用标题只识别实验、因子、Research Skill 等旧 ID 字段，没有识别 `definition_id`、`strategy_source_id`、`case_id` 等 Playbook ID；打开引用也没有对应只读分支。
- 修复：补齐 StrategySource、Definition、Case、Validation、SourceLink 和 ExpertSource 的标识字段；点击后在当前窗口右侧读取并展示精确只读记录。
- 相关文件：`src/quantlab/desktop/research_chat.py`、`tests/test_research_chat_desktop.py`。
- 验收：最终复测显示全部 UUID；StrategySource 引用可在当前窗口打开并显示标题、URL、哈希和完整性。

### BUG-07：模型使用 `limit=50` 导致连续三次工具失败、无正文

- 现象：复测会话 `69ae4fde-e728-4abb-8075-5d703bb70092` 中，模型连续对 `list_strategy_sources`、`list_playbook_definitions`、`list_playbook_validations` 传入 `limit=50`；工具 Schema 上限为 20，三次均失败，运行时直接终止并留下空白回答。
- 根因：虽然 Schema 已声明上限，模型仍可能生成越界分页值；只依赖模型遵守 Schema 不足以保证用户流程。连续失败保护又采用抛错方式，模型没有收尾机会。
- 修复：运行时根据工具 Schema 将只读列表的过大 `limit` 自动限制到最大值，并在 warning 中保留原请求值；连续三次失败时返回 `TOOL_FAILURE_LIMIT` 要求基于已有证据收尾，不再直接抛错生成空白页。
- 相关文件：`src/quantlab/agent/chat_runtime.py`、`tests/test_agent_chat.py`、`tests/test_research_chat.py`。
- 验收：同样的 `limit=50` 会按 20 执行并返回成功结果；连续失败回归测试仍能得到最终正文。

### BUG-08：只增加工具次数，没有同步上下文预算

- 现象：复测会话 `8c5ecfbd-1efc-4f06-a499-360960f165ea` 在 24 次工具上限下执行到第 17 次时，60000 字符上下文被工具摘要占满，最终仍以“工具摘要超过上下文预算”空白结束。
- 根因：Agent Memory 与系统说明已占约 3.8 万字符；工具次数从 12 翻倍后，上下文仍维持 60000，且运行时没有为最终回答预留空间。
- 修复：当前项目上下文预算调整为 120000；运行时按输出预算预留最终回答空间。工具摘要达到预留边界时返回 `TOOL_CONTEXT_BUDGET_EXHAUSTED`，停止继续查询并要求用已有证据作答，而不是抛错。
- 相关文件：`src/quantlab/agent/chat_runtime.py`、`tests/test_agent_chat.py`。
- 验收：最终会话在 18 次工具调用、49438 input tokens 下完成 2416 output tokens 的正文。

### BUG-09：扶摇 MCP 不能直接全量暴露给模型

- 风险：扶摇当前跨服务公开大量原始工具；直接挂给模型会扩大查询面、工具选择和上下文消耗，并可能让凭证边界落入模型配置。
- 修复：新增宿主侧 Streamable HTTP MCP 客户端，只连接固定的 meta、A 股和 A 股指数端点；同时执行本地代码白名单与服务端 `tools/list` 双重校验。模型只看到 5 个有界聚合工具，API Key 只从环境变量或 macOS 钥匙串读取。
- 相关文件：`src/quantlab/agent/fuyao_mcp.py`、`src/quantlab/agent/fuyao_tools.py`、`src/quantlab/agent/chat_runtime.py`。
- 验收：模型 Schema 包含 5 个聚合工具，不包含 `get_a_share_prices_snapshot` 等远端原始工具；密钥扫描无命中。

### BUG-10：新增外层工具包装器破坏既有提案服务访问

- 现象：首次接线后，原回归测试通过 `runtime.api.proposals` 访问提案服务时出现 `AttributeError`。
- 根因：新的 `FuyaoResearchAPI` 是最外层包装器，但未透传既有 API 链的宿主属性。
- 修复：增加 `__getattr__` 透明转发；扶摇只扩展 Schema 和调用，不替换原 Research Skill、Playbook、Peer Review、Session Grant 与 Proposal 服务。
- 验收：原“提案具有宿主 ID 且不执行”测试恢复通过；完整相关回归 28 项通过。

### BUG-11：新行情源接入后仍沿用旧来源文案

- 现象：实时行情失败提示与限制仍写“公开行情源/公开网页行情”，无法说明扶摇主源和公开网页交叉校验的关系。
- 修复：统一为宿主行情源；正常结果保留 `provider`、`agreement_sources`、`consensus_issues` 与 `completeness`。扶摇失败时回退原三站共识；数值冲突时标为 `PARTIAL`，不静默择值。
- 相关文件：`src/quantlab/trading/fuyao_market_snapshot.py`、`src/quantlab/agent/live_stock_quote.py`。
- 验收：宏景科技真实只读回读返回 `fuyao-with-public-cross-validation-v1 / FULL`，来源为扶摇、腾讯、东方财富、新浪，冲突数为 0。

### BUG-12：MCP 会话错误、限流与凭证泄漏边界

- 风险：对鉴权失败、限流或业务错误自动重试会放大请求；远端错误文本若回显敏感值可能进入对话证据。
- 修复：只对 HTTP 400/404 的失效会话重建一次；HTTP 429 与业务码 4001 不立即重试；禁止跨域重定向；错误和数据递归脱敏；响应体限制 2MB。
- 验收：握手、Session Header、`tools/list`、业务信封、白名单、错误脱敏与回退测试通过。
