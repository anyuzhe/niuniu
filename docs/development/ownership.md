# 牛牛六职责开发协作

[开发规范](contributing.md) · [代码地图](code-map.md) · [使用指南](../guide/user-guide.md#开发工作台六职责协作)

## 专业职责与过程权限

2026-09-25 起，开发工作台在原 P10 之上提供六职责模式。LEAD 是总控与集成；DATA 维护市场数据接口与治理代码；CORE 维护研究、策略、统计、回测和账户；AI 维护模型、会话、工具与编排；APP 维护产品界面；QA 独立测试与审核。角色可使用相同或不同模型，不要求每项需求都派齐四个实施域。

专业职责和过程权限是两个维度：EXPLORER 只读探索；IMPLEMENTER 才能写文件；TESTER 只运行冻结测试；REVIEWER 只读审核。LEAD/QA 不能成为 IMPLEMENTER；TESTER/REVIEWER 必须属于 QA。QA 的测试与审核是分开的子任务和模型上下文，并不表示必须使用两种不同模型。

## 文件归属

程序规则在 [team.py](../../src/quantlab/devstudio/team.py) 的 `EXACT_OWNERS`、`PREFIX_OWNERS`。精确规则优先，随后按最长前缀；未知或第三方受保护文件不能自动分配。普通任务不能通过模型传来的字段覆盖这些规则。

| 领域 | 默认范围及重要例外 |
|---|---|
| DATA | `data/`、`scripts/collect/`、`agent/tdx_*`；`agent/live_stock_quote.py`、扶摇接口、`trading/market_snapshot_provider.py` 和公开行情实现虽然跨目录，也归 DATA |
| CORE | 因子、实验、统计、执行、交易、存储与领域合同；`data/provider.py`、`data/mqc.py`、`data/dataset_catalog.py` 和 `workbench/jobs.py` 是消费/执行边界的例外 |
| AI | `agent/`（扣除 DATA 例外）、`devstudio/`、`knowledge/` |
| APP | `desktop/`、`workbench/`（扣除 CORE 例外） |
| 共享 | 普通测试和说明在确认计划中逐文件分配唯一实施负责人；DATA 清单仍固定归 DATA。LEAD/QA 不直接写共享文件 |

`path_owners` 必须精确覆盖本任务的 `allowed_paths`，六职责模式不允许目录级授权。租约只能使用已批准、属于自身领域的文件，不允许两个实施子任务认领同一文件。需要修改其他领域时，由 LEAD 创建对应领域任务；需要增加未批准的文件时，应停止并重新规划/确认，不得自行扩张。

公共序列化/摘要、领域合同、审批冻结、策略包、开发控制代码、运行时 Agent Memory 和 DATA 清单会在计划里标成敏感文件；标记是人工复核提示，不是自动审计结论。DATA 开发角色只是编写隔离代码，不因此得到正式数据写入、来源裁决或数据发布的执行权限。DATA 的事实合同继续以 [数据清单](../reference/data-catalog.md) 为准。

## 需求到交付

`输入需求 → LEAD 只读规划 → 人工确认需求/文件/测试/模型 → 创建隔离 DevTask → 按领域拆子任务 → 实施 → QA 测试 → QA 独立审核 → LEAD 核对 → READY_FOR_HUMAN → 人工合并`。

规划只能读取 Git 跟踪的代码、检索和提交计划，不创建任务或 worktree。计划绑定仓库、分支、精确 Git SHA、原始需求、完整任务合同及内容摘要，30 分钟后过期；基线变化或需求修改时重新规划。各角色完整模型配置随任务冻结，后改“六角色模型”不影响旧任务。配置仅保存密钥环境变量名，不保存密钥。

默认最多两个实施者并行，测试和审核在稳定工作区内独占执行。默认一次“运行/继续”最多六轮总控协调，合同上限八轮；每个子任务最多执行三次。失败保留原始记录，总控可重开同一实施任务；依赖它的测试和审核会失效并重做。依赖环、失败依赖、没有进展和超预算均阻断，而不是继续制造成功状态。

每个 DevTask 有一个 detached worktree，子任务在其中使用互斥文件租约，**不是每个专业角色一个长期分支**。通过 Git common-dir 的非阻塞锁，产品管理的执行/合并入口对同一仓库串行；不同输出目录不能重复启动。这个锁不强制约束外部编辑器、WebCodex 或绕过本产品的宿主进程，也不能替代对并行宿主修改的检查。

大文件用 `dev_read_range` 分段读取，通过 `dev_replace_text` 对唯一文本作精确替换；修改已有文件必须带读取时 SHA。全文件写只用于确有需要的实现，新建文件仍受同一精确租约保护。

## 测试与最终合并

六职责任务冻结逐模块 unittest 命令，例如 `python -m unittest discover -s tests -p test_example.py -v`。模型不能替换命令。测试引导器优先加载当前 worktree 的源码并检查实际 `quantlab` 路径；使用离屏 Qt、临时数据根并去掉常见凭据环境变量。零测试、全部跳过和源码在测试中变化不能通过。

**这些测试运行在宿主 Python 中，不是操作系统沙箱。** 允许列表控制模型工具，无法阻止被批准的 Python 测试主动访问宿主其他路径、网络或服务。只能批准已审阅的离线/隔离测试；不应把该功能当作不可信仓库执行沙箱。真正容器/进程级能力隔离尚未实现。

测试、Reviewer PASS、LEAD 验收都绑定当前工作区指纹。人工合并前再次检查三者与最终内容一致，检查主分支仍是创建任务时的分支和 SHA，主工作区干净。主分支前进时保留隔离改动并拒绝合并，不自动 rebase 或沿用旧验收；需宿主处理基线并重新测试。合并只创建本地提交，不自动 push、部署或修改业务运行授权。

请求停止会阻止后续模型工具和子任务派发；已经运行的测试需退出或达到冻结超时后才返回，不能把“请求停止”写成进程已结束。退出客户端后不承诺开发继续执行；重新进入工作台可查看持久任务，点击“运行/继续”会把失去执行者的 RUNNING 状态转成待检查的中断记录，交总控处理。

旧任务和“高级 DevTask”保留旧合同兼容，不凭空升级为六职责；研究助手和 AI Team 的研究角色不获得开发写入工具。
