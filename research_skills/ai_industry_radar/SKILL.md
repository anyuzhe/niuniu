# AI 产业雷达方法 Research Skill（控制包）

## 来源与当前状态

本 Git 跟踪目录保持 `SOURCE_REQUIRED` 控制包：不复制第三方原始语料或外部脚本。上游是用户自有公开仓库 `ai_industry_radar_pyqt`，它依据两段第三方视频逐字稿做了工程化复刻。宿主授权 clone 的上游身份固定在 `upstream.lock.json` 所列 commit/tree；全部 tracked blobs 以内容寻址对象和 append-only receipt 保存在独立数据根。策展包只能从该 receipt 选择资源生成，仍是回顾性 DRAFT。

来源分三层，不得混用：

1. **视频博主的口述观点**：以仓库内“精校逐字稿”作为 `PRIMARY_STATEMENT`。它是二次转写并经过同音错字校勘，不是博主发布的原始音视频字节；视频中的样本量、胜率和收益均为博主自述。
2. **雷达仓库的工程化复刻**：README、设计文档和手写产业链配置只作 `DOCUMENTATION`，属于复刻者的设计与假设，不是来源原话。
3. **牛牛自己的数据与研究**：唯一可以检验上述观点的地方。

## 目标行为

1. 引用观点时区分 `DIRECT_QUOTE`（逐字存在于精校逐字稿）、`METHOD_INFERENCE`（由原话推导的方法）与 `FACT_TO_VERIFY`（博主自述的统计数字）。
2. “热度即拥挤度报警”和“产业上游 + 未来确认时刻”只能作为 DRAFT 假设和候选特征进入牛牛；方向、窗口、分组、成本与样本外检验由牛牛自己预注册并执行后再决定取舍。
3. “未入选标的进入影子组合作为对照组”对应牛牛宿主已实现的 Playbook 选择结果复盘（同一冻结 CandidateSet 内选中 vs 未选中的信号收益对照）；它只是选择诊断，不自动调权。

## 禁止行为

- 不把热榜、人气排名或题材热度当正向买入分；在牛牛自己完成检验前，也不把它当确定的反向信号。
- 不把雷达仓库的评分公式、权重、闸门阈值或 `lead_days` 当成已验证规则移植；缺失维度既不能用中性值填补，也不能按剩余权重重新归一化来补齐总分。
- 不把博主自述的样本数、胜率、超额收益当成牛牛的验证结果或 Alpha 证据。
- 不用当前题材成分回看历史去计算“题材年龄/持续天数”并当作 PIT 事实。
- 不自动执行 `scripts/`，不自动联网，不写 StrategySource/Playbook，不创建 Decision、Paper 或订单。
