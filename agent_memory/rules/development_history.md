# 开发历程与功能变更总档案维护规则

权威人类可读开发史文件：

`/牛牛AI交易助手_开发历程与功能变更总档案.md`

## 强制要求

任何 Agent 在完成以下改动时，都必须同步检查并追加该总档案：

- 新功能、新页面、新 CLI/MCP/daemon/服务。
- 架构、权限、Agent、模型路由、记忆或工作流变化。
- 数据合同、PIT、回测、执行、Playbook、研究结论语义变化。
- 重要 Bug 修复或兼容性变化。
- 测试基线、部署方式、阶段计划或发布状态变化。

## 条目要求

至少记录：日期时间、类型、模块、改动内容、原因、关键约束、测试/验收、Git提交、后续事项。

如果提交已经完成但开发史未更新，应在同一任务收尾前补齐；不能只依赖 commit message、聊天记录或阶段验收文档。

临时 scratch、Git 忽略的原始网页/行情快照和无行为影响的纯调试输出无需逐条记录；一旦它们导致正式功能/规则/结论变化，必须记录正式变化。

## 证据边界

总档案用于叙述开发过程，不替代 Git、结构化 Research Evidence、Decision、Theme、Playbook、Watch、交易归档或测试日志的权威事实。
